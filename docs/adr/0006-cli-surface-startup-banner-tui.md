# ADR 0006：CLI 命令面、彩色 ASCII 启动横幅与 TUI 仪表盘

日期：2026-11-06。状态：已确认（用户 2026-11-06 答复 Q6 及其两轮修订）。

## 决策

**八个顶层命令**：`init`（建工作区）、`import`（导入材料）、`claims`（候选陈述）、`draft`（生成草稿）、`review`（审阅与冲突）、`export`（导出）、`eval`（冻结 fixture 评测）、`dash`（TUI 仪表盘）。更多操作做成子命令，不加新顶层命令。生成类操作统一带 `--max-steps`、`--max-cost` 上限参数。

**启动横幅**：裸运行 `psychtool`（无子命令）时显示彩色 ASCII logo 横幅（参照 Hermes 式启动体验）+ 版本号 + 当前 `data_tier` 状态 + 命令列表。`data_tier: synthetic` 用绿色，`real` 用红色并在顶部追加网络禁用警示行。终端不支持颜色时降级为纯文本。

**`dash`**：基于 `textual` 的 ASCII TUI 仪表盘，是**第一阶段的主要交互界面**，不是子命令的附属浏览器的地位。工作区列表、候选陈述核对、草稿与来源跳转、冲突标注、评测结果一览都在其中可操作；命令行子命令作为脚本化/自动化入口与其并存，两者功能对等。与启动横幅同一配色。

裸运行 `psychtool` 显示启动横幅后直接进入 `dash`（可用 `--no-dash` 跳过只显示横幅）。

## 理由

- TUI/横幅仍在终端内，面向开发者，不违反 ADR 0001 的「界面推迟」。
- 目标用户审美为学术 + ASCII 可爱；启动仪式感是低成本高辨识度的产品性格。
- `data_tier` 状态每次启动可见，把隐私边界从配置项变成持续的环境信号。
- 分层：横幅、TUI、子命令共用同一核心库；界面层崩溃不影响命令行功能。

## 后果

- 依赖新增 `rich`（渲染）与 `textual`（TUI）；核心库不得 import 这两个包，保证无界面环境可用。
- logo 字形入库为文本文件，随版本管理；README 的 mono 学术视觉与 CLI 彩色终端是两种语境，各自克制。
