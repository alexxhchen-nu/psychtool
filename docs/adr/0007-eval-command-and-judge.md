# ADR 0007：`eval` 为独立命令；硬门槛纯代码，语义指标 LLM judge + 留档

日期：2026-11-06。状态：已确认（用户 2026-11-06 答复 Q7）。

## 决策

评测实现为 CLI 的独立 `eval` 命令，跑冻结 fixture，输出结构化报告（JSON + 可读摘要）。与 pytest 分离：pytest 测程序正确性，`eval` 测「模型+流程」的行为。

指标分层：

- **硬门槛（纯代码判定，失败即阻断候选版本）**：跨个案泄漏、编造关键事实、矛盾静默消失、来源失效后沿用旧核对状态。
- **语义指标（LLM-as-judge 打分 + 人工抽检）**：逐陈述支持率等。judge 的提示词与每条原始判定写入报告存档，可复查；模型自产的判定不作为唯一真值。

## 理由

- 规格中的阻断门槛都是可机械判定的结构性质，不依赖语义理解，适合纯代码。
- 「引用语义上是否支持陈述」无法纯代码判定，用 judge 但必须留档——避免模型自证其正确。

## 后果

- judge 与生成模型在配置上是两个独立槽位，允许不同供应商。
- 报告包含每项指标的值、判定依据指针、冻结 fixture 版本指纹。
