# ADR 0001：第一阶段交付开发者 CLI，界面推迟

日期：2026-11-06。状态：已确认（用户 2026-11-06 答复 Q1）。

## 决策

第一阶段交付**开发者使用的本地命令行工具**：输入合成 fixture，输出带来源的草稿与评测报告。面向学生的图形界面推迟到核心评测通过之后。

## 理由

- 「模型/流程是否正确」与「界面是否易用」是两个独立变量；混在一起会污染首轮评测结论。
- 验收场景（隔离、溯源、矛盾保留、来源失效）全部可在 CLI 层验证，不依赖界面。
- 学生无技术背景，但她不是第一阶段的操作者；开发者是。

## 后果

- 界面需求（操作步骤、文案、错误提示）在评测通过后另行设计，届时 CLI 的稳定行为成为界面规格的输入。
- 风险：CLI 阶段积累的结构若未预留界面边界，日后包壳成本高。缓解：命令层与核心逻辑分层，核心逻辑以库形式实现。
