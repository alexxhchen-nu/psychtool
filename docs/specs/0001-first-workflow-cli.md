# SPEC 0001：psychtool 首个工作流 CLI（合成材料阶段）

日期：2026-11-06。状态：待确认接缝后生效。
来源：grill-with-docs 两轮结论（ADR 0001–0008）、`docs/first-workflow-spec.md`、`docs/clinical-requirements.md`、`GLOSSARY.md`。

## Problem Statement

临床培训生需要把获准使用的个案材料整理成带来源的报告草稿。在为使用者构建界面之前，开发者需要先在完全虚构的材料上证明：整理流程能保留归属、矛盾与未知，能严格隔离个案，且每条草稿陈述可回溯到来源段落。目前仓库只有文档与 fixture，没有任何可运行的程序，评测无法进行。

## Solution

一个本地命令行工具 `psychtool`：管理个案工作区（目录 + 版本化 JSON），从材料整理候选陈述，按选定事实生成带来源索引的背景草稿，支持人工核对、冲突标注与导出；内置 `eval` 命令在冻结 fixture 上跑行为评测，硬门槛失败即阻断候选版本。裸运行显示彩色 ASCII 启动横幅并进入 `dash` TUI 仪表盘（第一阶段主要交互界面）。

## User Stories

1. 作为开发者，我想运行 `psychtool` 后看到彩色 ASCII logo、版本与当前数据档状态，以便确认我在正确的工具与隐私档位里。
2. 作为开发者，我想在 `data_tier: synthetic` 时看到绿色状态、在 `real` 时看到红色状态与网络禁用警示，以便隐私边界始终可见。
3. 作为开发者，我想 `init` 创建个案工作区并显式标记其完全虚构状态，以便训练材料与真实材料在结构上就不可能混淆。
4. 作为开发者，我想 `import` 文本材料并得到标题、提供者、日期、段落定位与版本号，以便后续一切引用都有定位。
5. 作为开发者，我想修改已导入材料时产生新版本而非覆盖，以便旧来源定位仍可查看。
6. 作为开发者，我想 `claims` 列出候选陈述并保留本人/他人/人工解释的归属区别，以便逐条人工核对。
7. 作为开发者，我想并排查看同一主题下的差异陈述并标注「冲突已查看」而不删除任何原始陈述，以便矛盾被显式保留。
8. 作为开发者，我想 `draft` 只基于我已选定的同一工作区候选陈述生成背景段落，以便生成边界可控。
9. 作为开发者，我想草稿中每条事实性陈述可点击/查询定位到来源段落，以便逐条回溯。
10. 作为开发者，我想缺失内容在草稿中明确显示为「未知」而非被猜测填补，以便事实边界不被突破。
11. 作为开发者，我想修改来源后受影响的草稿被标记为需要重新核对、旧确认状态失效，以便不使用过时依据。
12. 作为开发者，我想 `review` 中查看所有冲突、缺口与失效引用，以便在导出前完成审阅。
13. 作为开发者，我想 `export` 由草稿与来源索引组成、导出前预览内容与目标路径，以便外发是可审计的主动行为。
14. 作为开发者，我想 `eval` 在冻结 fixture 上分别运行单步生成与「抽取→生成」两种方案并输出结构化报告，以便用证据选择生成架构。
15. 作为开发者，我想硬门槛（跨个案泄漏、编造关键事实、矛盾消失、来源失效沿用）由纯代码判定且失败即阻断，以便安全性不依赖模型自觉。
16. 作为开发者，我想逐陈述语义支持率由独立槽位的 LLM judge 打分且判定原文存档，以便语义指标可复查且非模型自证。
17. 作为开发者，我想评测报告包含 fixture 版本指纹与每项指标的判定依据指针，以便结果可复现。
18. 作为开发者，我想生成类操作受 `--max-steps` 与 `--max-cost` 限制、超限停止并保留已有工作，以便失控有界。
19. 作为开发者，我想材料中出现「忽略个案限制」类注入指令时只被当作原文显示，以便权限不被内容篡改。
20. 作为开发者，我想 `dash` 仪表盘里完成工作区浏览、陈述核对、冲突标注与评测结果查看，以便日常操作有主要交互界面。
21. 作为开发者，我想命令行子命令与 `dash` 功能对等，以便脚本化与自动化可行。
22. 作为开发者，我想所有模型调用只走单一 OpenAI 兼容出口、密钥只从环境变量读取，以便供应商可切换且密钥不入库。
23. 作为开发者，我想提示词模板是仓库内的版本化文件，以便行为变更可审计、可 diff。
24. 作为未来的学生用户，我（经由开发者）希望所有原始材料与生成内容分别保存、任何内容不被静默覆盖，以便我的记录始终完整。

## Implementation Decisions

- 模块划分：`core`（工作区、材料、事实清单、草稿、审阅、评测的全部逻辑；纯 Python，禁止 import rich/textual，禁止网络）、`gateway`（唯一网络出口，OpenAI 兼容接口；读取 `data_tier` 决定放行/拒绝）、`cli`（typer 命令层）、`tui`（textual 仪表盘）、`banner`（启动横幅，rich 渲染，无颜色终端降级纯文本）。
- 数据模型：工作区 = 目录；材料/候选陈述/草稿/审阅记录 = 带 `id`、`version`、`case_id`、来源定位、状态字段的 JSON 文件；版本不可变，修改写新文件（ADR 0005）。
- 候选陈述字段（承袭 `docs/first-workflow-spec.md` 数据约定）：所属个案、来源文档与段落、提供者角色、观察场景、记录时间、所述事件时间、陈述类别、原文、核对状态；未知事件日期不得以文档日期代替。
- 段落定位：文档版本 + 段落 ID；PDF 支持留待后续。
- 模型配置三项：`base_url`、`api_key`（仅环境变量）、`model`；生成模型与 judge 是两个独立槽位（ADR 0007/0008）。
- 命令面：`init` / `import` / `claims` / `draft` / `review` / `export` / `eval` / `dash` 八个顶层命令；裸运行 = 横幅 + 进 `dash`（`--no-dash` 跳过）；生成操作统一 `--max-steps` / `--max-cost`（ADR 0006）。
- 启动横幅：ASCII logo 字形入库为文本文件；`synthetic` 绿、`real` 红 + 网络禁用警示行。
- 评测执行：冻结 fixture（`fixtures/adolescent-background.json`、`fixtures/source-fidelity-variants.json`）只读输入；报告 = JSON + 可读摘要；含 fixture 版本指纹。
- 硬门槛实现为纯代码检查：跨个案内容出现在输出、输出含参考事实表未提供的诊断/分数、已标注矛盾在草稿中静默消失、来源失效后沿用确认状态。
- 注入防护：材料内容只进入「数据」位置，永不作为指令拼接；网关层不解析材料文本为命令。

## Testing Decisions

- 好测试的标准：只测外部可观察行为（命令输出、文件产物、退出码、报告内容），不测内部函数如何拼接；评测断言冻结 fixture 的期望行为而非实现路径。
- 接缝 1（`core` 公共 API）：工作区生命周期、版本不可变性、核对状态失效、个案隔离、注入内容惰性化——单元级，占测试主体。
- 接缝 2（CLI 端到端）：子进程跑真实命令，覆盖八个命令、横幅输出（含无颜色降级）、`--max-*` 超限行为、退出码。
- 接缝 3（网关出口）：假传输桩验证 `real` 档拒绝网络、`synthetic` 档放行、提示词模板渲染与密钥来源——不打真 API。
- `dash`：快照/冒烟测试（能启动、能渲染主要面板），不重复测核心逻辑。
- 先验参照：仓库无既有测试套件；`fixtures/` 的期望行为字段即首批测试数据的来源。

## Out of Scope

- 图形界面（桌面/Web）与打包分发。
- PDF 导入、OCR、真实个案数据、`data_tier: real` 的实际启用。
- DSM/量表/商业材料的任何形式入库。
- 文献库上下文（论文检索与引用管理）。
- 多用户、云同步、崩溃上报、遥测。
- 评测之外的真实模型质量结论（首轮只出对比数据，不下「哪种方案更安全」的结论直到人工复核）。
