# Domain Docs

工程技能探索本仓库时如何消费域文档。

## 探索前先读这些

- **`GLOSSARY.md`**（仓库根，单上下文）。
- **`docs/adr/`**：读与当前工作区域相关的 ADR。

若这些文件不存在，**静默继续**。不要提示缺失，也不要主动建议创建。`/domain-modeling` 会在术语或决策真正落定时惰性创建它们。

## 文件结构

单上下文仓库：

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-cli-first-gui-later.md
│   └── …
└── docs/specs/
```

## 使用术语表词汇

当输出命名域概念（issue 标题、重构提案、假设、测试名）时，使用 `GLOSSARY.md` 定义的术语，不漂移到术语表明确避免的同义词。

若所需概念不在术语表中，那是信号：要么你在发明项目不用的语言（重新考虑），要么存在真实缺口（记下交给 `/domain-modeling`）。

## 标记 ADR 冲突

若输出与既有 ADR 冲突，显式指出，而非静默覆盖：

> _与 ADR-0007 冲突，但值得重新打开，因为……_
